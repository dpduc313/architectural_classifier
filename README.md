# Heritage Building Image Dataset Preprocessing

This repository contains a data preprocessing pipeline for preparing heritage building images for computer vision training. It takes raw, lightly organized images and standardizes them by generating embeddings, removing duplicates, flagging outliers, and generating a stratified split.

## Directory Structure

- `raw_data/`: Contains the original images, organized in subfolders by building ID/style.
- `execution/`: Contains the Python scripts for each step of the pipeline.
- `.tmp/`: Contains intermediate outputs generated by the scripts (manifests, embeddings, checkpoints, etc.).

## Pipeline Progress

- [x] **1. Scan and Manifest** (`execution/scan_and_manifest.py`)
  - Scans `raw_data/` and builds an initial catalog of 9,740 images with their style labels (A1, A2, B1, B2).
  
- [x] **2. Compute Embeddings** (`execution/compute_embeddings.py`)
  - Extracts DINOv2 embeddings for every image to assist in duplicate and outlier detection.
  
- [x] **3. Detect Duplicates** (`execution/detect_duplicates.py`)
  - Clusters images based on cosine similarity of their embeddings to find near-exact duplicates.
  
- [x] **4. Detect Outliers** (`execution/detect_outliers.py`)
  - Flags images whose embeddings deviate significantly from the rest of their class (unhelpful data).
  
- [x] **5. Split Dataset** (`execution/split_dataset.py`)
  - Generates a stratified train/val/test split grouped by `building_id` to prevent data leakage.
  
- [x] **6. Preprocess Images** (`execution/preprocess_images.py`)
  - Resizes, cleans, and deduplicates the images based on the policies defined per split.
  
- [x] **7. Sanity Checks** (`execution/sanity_checks.py`)
  - Verifies class balance and ensures no `building_id` overlap between splits.

## Phase 2: Model Training (run after pipeline completes)

- [x] **8. Train all models** (`execution/training/train.py`)
  - Trains ResNet-50, ViT-B/16, DINOv2-S, and Swin-V2-T using 2-phase fine-tuning.
  - Run each model separately:
    ```powershell
    .venv\Scripts\python.exe execution/training/train.py --model resnet50
    .venv\Scripts\python.exe execution/training/train.py --model vit
    .venv\Scripts\python.exe execution/training/train.py --model dinov2
    .venv\Scripts\python.exe execution/training/train.py --model swinv2
    ```
  - Best checkpoints saved to `.tmp/checkpoints/{model}_best.pt`
  - Training logs saved to `.tmp/logs/{model}_train_log.csv`

- [ ] **9. Evaluate on test set** (`execution/training/evaluate.py`)
  - Loads all checkpoints and runs test inference.
  - Outputs: per-class F1, confusion matrices, misclassified examples.
    ```powershell
    .venv\Scripts\python.exe execution/training/evaluate.py
    ```

- [ ] **10. Compare models** (`execution/training/compare_models.py`)
  - Prints and saves a side-by-side comparison table of all 4 models.
    ```powershell
    .venv\Scripts\python.exe execution/training/compare_models.py
    ```

- [ ] **11. Grad-CAM visualisation** (`execution/training/gradcam_vis.py`)
  - Generates Grad-CAM overlays for Swin-V2 on test images.
  - Requires: `pip install grad-cam`
  - Output saved to `outputs/gradcam/`
    ```powershell
    .venv\Scripts\python.exe execution/training/gradcam_vis.py
    ```

## How to Run (Phase 1 — Data Pipeline)

Ensure the virtual environment is activated, then run the scripts in sequence:

```powershell
.venv\Scripts\python.exe execution/<script_name>.py
```

## Future Work & Optimization Directions

For the next stage of development to maximize model performance and utilize hardware efficiently, the following optimizations are planned:

1. **Data Augmentation**:
   - Integrate advanced augmentation strategies such as **Mixup**, **CutMix**, **RandAugment**, and **ColorJitter** to improve generalization against real-world variations (weather, shadows, angles).
2. **Training Optimization**:
   - Implement **Cosine Annealing Learning Rate Schedulers** with a warmup phase.
   - Use **Layer-wise Learning Rate Decay (LLRD)** for Transformer-based architectures.
   - Apply weight decay and Stochastic Depth to prevent overfitting on the patch dataset.
3. **Parallel Processing & Acceleration**:
   - Enable **Automatic Mixed Precision (AMP / FP16)** to reduce memory consumption and accelerate training on GPUs.
   - Utilize PyTorch **Distributed Data Parallel (DDP)** for multi-GPU setups.
